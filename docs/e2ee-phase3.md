# ЯЧат E2EE — этап 3: зашифрованные вложения

Этап 3 дополняет защищённые личные чаты шифрованием бинарного содержимого вложений на устройстве отправителя.

## Что изменилось

- байты фото, видео и файлов шифруются AES-256-GCM до отправки;
- исходные имя, MIME-тип, вид, размер и SHA-256 отпечаток файла находятся внутри зашифрованного сообщения;
- сервер получает только технический контейнер `application/vnd.yachat.e2ee`, его размер и идентификатор;
- после расшифровки клиент восстанавливает обычное вложение для просмотра и скачивания;
- изменение ciphertext, IV, контекста, размера или порядка вложений приводит к отказу проверки сообщения.

Ключ вложений не передаётся отдельно. Для каждого сообщения создаётся случайный content key, который уже доставляется устройствам участников через E2EE envelopes. Каждое вложение использует отдельный случайный 96-битный IV и AAD, привязанный к чату, сообщению, позиции и исходным метаданным.

## Совместимое включение

Протокол версии 3 используется для сообщения с вложением только тогда, когда сервер подтвердил поддержку `encrypted-attachments-v1` всеми активными устройствами и недавно использованными сессиями участников.

Если хотя бы одно активное устройство поддерживает только этап 2, сообщение сохраняет протокол версии 2: текст остаётся сквозно зашифрованным, а вложение — серверным объектом с защищённым контрольным отпечатком. Это не выдаётся за полное шифрование файла.

Текстовые сообщения без вложений остаются в формате версии 2, поэтому переход не ломает уже готовые клиенты этапа 2.

## Уведомления

Контур push-уведомлений этим этапом не изменяется: существующий заголовок, текст и логика доставки сохраняются.

## Что сервер всё ещё видит

- участников и активные устройства личного чата;
- отправителя и время сообщения;
- факт и количество вложений;
- размер каждого зашифрованного контейнера;
- размер ciphertext сообщения.

## Что пока не входит

- Double Ratchet и удаление старых message keys;
- sender keys для групп;
- резервное копирование ключей и QR-проверка safety number;
- безопасная выдача старой истории новому устройству;
- сокрытие размеров и количества вложений.
